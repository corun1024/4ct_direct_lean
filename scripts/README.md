# Scripts

Everything under `FourColor/` is hand-written or generated by a script here, and every
generated module is checked by lazylean like any other: nothing in this directory is trusted.

## Generated modules

* `gen_reducible.py` writes `FourColor/Reducible/`: 49 job modules, 10 task modules and
  `All.lean`, after the reference's `job*.v`, `task*.v` and `reducibility.v`. One theorem per
  configuration, `red_cfNNN : checkReducible cfNNN = true := by decide +kernel`, then the range
  lemma of the job assembled with `check_reducible_in_range`, and the chaining with
  `cat_reducible_range`. Deterministic; re-run it after changing the partition or the template.
* `FourColor/Configurations.lean` (the 633 configurations) and `FourColor/Present<n>*.lean`
  (the seven presentation scripts) were translated mechanically, once, from
  `configurations.v` and `present<n>.v` of the reference development
  ([rocq-community/fourcolor](https://github.com/rocq-community/fourcolor), CeCILL-B; none of
  its text is copied into this repository), and the results are committed.
  `FourColor/QuizData.lean` and `QuizTreeData.lean` were then derived from
  `Configurations.lean` by a Lean computation.

## Verification

Lean's kernel is off for every module (`lakefile.toml`), so `lake build` elaborates and proves
nothing. The proof is checked here:

* `verify.sh [outdir]` exports the dependency closure of the theorem and of the audit
  theorems, and the closure of the 633 reducibility theorems alone; checks the first with
  lazylean in shards (the reducibility declarations listed as trusted), then each reducibility
  declaration on its own from the second; and writes `outdir/SUMMARY.md`. Needs `LAZYLEAN` and
  `LEAN4EXPORT` (defaults `~/lazylean/build/lazylean`, `~/lean4export/.lake/build/bin/lean4export`).
* `schedule_reducible.py` runs the 633 checks one process each, heaviest first, under a memory
  budget: a ring-14 configuration needs about 21 GB, a ring-13 one about 4.5 GB.
* `RingSizes.lean` prints each configuration's ring size for the scheduler.
* `summarize.py` demands 0 failures in both steps, lists the axioms the export declares, prints
  the theorem's type as lazylean read it, and exits non-zero otherwise.
* `check.sh` is the old guard: no `sorry`, `native_decide`, `axiom`, `partial`, `unsafe` or
  `opaque`, `debug.skipKernelTC` nowhere but the lakefile; then `Check.lean` walks the axioms of
  every `FourColor` declaration in the elaborated environment and confirms
  `FourColor.fourColorTheorem : FourColor.FourColorTheorem` is present; then it demands a clean
  verification summary.
* `synth_decide.py` writes `d = true := Eq.refl true` theorems straight into an export, with no
  elaborator involved; it is how the timing ladder in the README was run.
